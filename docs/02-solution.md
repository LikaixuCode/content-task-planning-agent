# 设计与取舍

## 调用链

CLI 校验输入并登记请求 → SDK 将四个进程内工具提供给 GLM → 模型选择工具并观察实际返回 → 本地规则计算成本、工期与依赖 → SQLite 保存状态和方案 → 程序按存储结果输出。

Claude Agent SDK 0.2.175 负责模型会话与工具循环，使用 `@tool` 和 `create_sdk_mcp_server` 注册业务工具；`tools=[]`、`strict_mcp_config=True` 和 `setting_sources=[]` 不加载额外工具。SDK 的 `max_turns` 限制模型轮次；业务层另外限制工具实际执行次数，并拒绝超限调用。离线 Mock 用脚本驱动同一业务工具。

## 业务边界

- 费用表定义素材准备、不同版本的脚本和内容包装的模拟费用与耗时；使用十进制计算，不合并被放弃方案的估算值。模型 API 的真实开销不在模拟预算内。
- 估算以首次请求的 `start_at` 为起点，串行累加各项工期；比较带时区的截止时间。它不代表真实业务的日历、排班或耗时。
- 先检索素材，再估算所选素材与方案；生成脚本需要可行估算。保存需要同一估算的成功脚本，并重新检查费用和截止时间。
- 工具执行记录和当前结果写入 SQLite；方案保存在同一请求记录中。相同请求返回同一个方案，内容不同的同一请求 ID 报错。当前实现面向本地单进程使用，不提供多进程并发协调。
- 成功步骤作为状态保存；续跑时提供历史结果，已成功且输入和依赖数据相同的检索、估算或脚本可复用。素材变化会使检索及下游结果失效；费用表变化会使估算和脚本结果失效。被放弃的方案及失败记录仍保留在步骤记录中。
- 工具失败或上限中断不能由模型口头改成成功。储存写入失败时先读取现有状态；确认结果前不重放写入。方案任务的 `planned` 不代表活动实际完成。

## 模型与 Mock

真实模式将工具结果返回给 GLM，由模型决定估算替代方案、生成脚本、保存或停止；调用依据来自每次模型提供的 `reason`。`terminal.sdk_events` 记录 SDK 发出的工具请求、结果及对应 ID，可核对模型是否在收到结果后才发出下一次请求。Mock 的分支由本地脚本实现，其记录标明 `mode=mock`。
